## 2026-05-22 - Fix sensitive data leak in logger
**Vulnerability:** The logger in `utils/logger.ts` was sanitizing sensitive data (like `password`, `API_KEY`) when sending attributes to Sentry, but it passed the raw, unfiltered arguments directly to `rnLogger`, which logs to the local device console/files.
**Learning:** Logging abstractions that dual-write to multiple sinks (local vs. remote) must apply sanitization *before* distributing the payload to *any* sink. Furthermore, when recursively sanitizing objects, `Error` instances must be explicitly handled (e.g., `if (arg instanceof Error) return arg;`) to preserve stack traces instead of wiping them as generic objects.
**Prevention:** Apply data sanitization and redaction at the very beginning of the logging pipeline, and ensure custom generic object traversal explicitly ignores prototype-heavy native classes like `Error`.
