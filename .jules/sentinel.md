## 2025-02-26 - Secure MMKV Encryption Key Generation
**Learning:** `Crypto.randomUUID()` generates a UUIDv4 which relies on PRNGs that are not cryptographically secure and should not be used for encryption keys. Furthermore, test environment fallback keys should be strictly guarded.
**Action:** Always use `Crypto.getRandomBytes()` or a proper CSPRNG for generating encryption keys, convert the output to a safe format like base64, and wrap test fallbacks in `__DEV__` or `NODE_ENV === 'test'` checks so they are stripped from production builds.
## 2025-02-27 - Fix Non-Existent API Call in PostgREST Filtering
**Vulnerability:** In Supabase's `postgrest-js` client builder, there is no `.regexIMatch` chained method for filter queries, which causes runtime and compilation failures when querying data.
**Learning:** `postgrest-js` exposes exact postgrest operators strictly through the `.filter(column, operator, value)` method. The `exactPostgrestPattern` function escapes regex syntax correctly but PostgREST relies on proper Postgres regex matching strings instead of custom methods. Attempting to call `.regexIMatch()` is an invalid invocation. Furthermore, properly sanitizing and escaping strings passed to `filter("column", "imatch", pattern)` ensures no regex injection (ReDoS) or wildcard injection occurs when mapping queries against Postgres.
**Prevention:** Always use the standard `.filter("column", "imatch", pattern)` format for filtering text instead of hallucinated methods, and always ensure regex strings are bound to start and end points via `^` and `$` explicitly while escaping the input properly to defend against ReDoS attacks on the database layer.
