🚨 Severity: HIGH
💡 Vulnerability: User input passed directly to Supabase's `.ilike()` methods in `BaseIngredientApi.ts` is vulnerable to wildcard injection. Characters like `%`, `_`, `*`, `?`, and `\` are evaluated as wildcards, allowing for unauthorized broad pattern matching and potentially slow query DoS attacks.
🎯 Impact: Attackers could craft inputs that match many more rows than intended, potentially bypassing intended search constraints or degrading database performance by triggering expensive wildcard searches.
🔧 Fix: Sanitized inputs in `getBaseIngredientByName`, `findIngredientBySynonym`, and `fetchIngredientsBySynonyms` by escaping these special characters using `.replace(/[%_*?\\]/g, "\\$&")` before passing them to `.ilike()`.
✅ Verification: The wildcard characters will be treated literally. Verify by searching for ingredients containing these characters, they should exact match instead of acting as wildcards. Note: pre-existing `bun run test` issues are due to environment toolchain incompatibilities (ts-jest) which I have been instructed not to touch.
